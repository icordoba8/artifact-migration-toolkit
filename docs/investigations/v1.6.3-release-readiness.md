## Findings F1–F4

| # | Disposition | Blocker? |
| --- | --- | --- |
| F1: archive bytes are not reproducible (`tar -czf` with no fixed mtime or order, gzip header) | **Documented limitation.** The release contract never pins the archive digest. The consumer bootstrap (`scripts/runtime-bootstrap.mjs`) requires an immutable release with exactly one asset carrying a digest that GitHub computed. It verifies the download against that digest, checks the manifest's toolkit identity against the tag commit, then re-verifies every file against the manifest. `release:record` takes `contentHash` from the published asset's manifest. The reproducible identities are `contentHash` and the manifest pin. So uploading **one** archive and recording **GitHub's published digest** of it satisfies the contract. `9e84b8c7…` in PR #13 is only the author's local build, and it is not a release identity. Deterministic archive reproducibility is **not** claimed. | No |
| F2: `pnpm install` chmods 10 engine bin files 100644→100755, so `release:check` sees a dirty tree | Operator procedure. Confirm the change is mode-only (`git diff --summary`), then restore it on the disposable release checkout before `release:check`. No content change. | No |
| F3: the target-binding check runs only while VERIFY_SLICES is the latest transition (`lifecycle/artifact-execution.mjs:462`) | **Documented limitation**, pre-existing; the engine is unchanged by the candidate. FINALIZE refuses the forgery. After COMPLETE, a re-read accepts a re-sealed `targetDigest` if the unkeyed history chain is also recomputed. This is the known unkeyed-chain limit. The M13.1 wording "refused on the completed record" overstates what is enforced, so release notes must not repeat it. | No (functional scope) |
| F4: a refused checkpoint document exits 0 with `outcome CONTINUE` and only a `Validation:` line | **Documented limitation**, by design (`exitCodeFor`). Automation must check the step and the `Validation:` line, never exit 0 alone. | No |

No unavoidable code change was found, so the candidate SHA stays as it is.
